# 开发阶段

第一阶段完成合同、识别适配、统一命令服务、HTTP API、Mock 执行器和两版装配。尚未实现真实 WPS API、Ribbon UI、任务窗格、安装器、云端部署、Cloudflare、遥测、正文修改、复杂编号、页眉页脚、表格和图片格式。

当前 wheel 已提供稳定的本地 SDK 和 CLI（docxtool-recognize），因此本阶段不再复制识别逻辑或另建识别服务；客户端通过受限的本地运行器适配该入口。

官方发布与真实宿主验证阶段：`wpsjs 2.2.3` 的涉密版开发注册已完成，两个 edition 均可构建并通过加载项静态校验。由于当前环境不允许启动或操控 WPS GUI，Ribbon、任务窗格、RuntimeProbe、活动文档读取和五类写入均为 `NOT_RUN`，阶段整体状态为 `REAL_WPS_E2E_PARTIAL`。

第三阶段提供 `e2e:classified:prepare/status/stop/report` 和开发验证任务窗格，供操作员手工执行真实 WPS 验收。`wpsjs publish` 交互式分发仍留到安装器阶段；本阶段继续使用已经成功的官方 `wpsjs debug` 开发注册。

任务窗格已升级为自动诊断面板：按依赖图执行只读检查、以稳定错误码分类跨端口失败、显示首个根因，并在导出时保存完整脱敏诊断列表。真实 WPS 写入仍不自动执行。

真实写入验证交互采用固定白名单测试值、观察期和恢复读回。它只面向当前 E2E 测试副本，不扩展任何排版命令或正文编辑能力。
